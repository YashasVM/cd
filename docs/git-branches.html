a tiny guide to Git

Branches, simply

A branch is a separate line of work in the same project. It lets someone make a change without disturbing the main version.

Working in parallel

  1. Each person or agent gets a branch for their task.
  2. They edit and save their work with commits on that branch.
  3. When it is ready, they open a pull request so the change can be reviewed.

Merging

Merging joins a finished branch back into the main branch. Git combines the changes. If two branches changed the same lines in different ways, Git asks someone to choose how those lines should look.

The usual flow

git switch main
git pull
git switch -c improve-the-page
# make changes, then save them
git add .
git commit -m "Improve the page"
git push -u origin improve-the-page
# open a pull request on GitHub

For agents to work at the same time without editing the same files in one folder, give each one its own branch and worktree. Merge each finished branch through a pull request.

Short version: branch → work → review → merge
