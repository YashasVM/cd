Which is faster?
The performance target is open across all required paths. Browser timings are recorded separately so interface overhead is visible alongside native transfer times.
Every answer belongs to its selected workload and route. The installed croc 10.7.0 baseline is downloadable, but the main comparison uses the verified 11.5.5 release.
Why speed changes
CD's TCP lane sends encrypted records over a native socket. WebRTC uses Pion SCTP over DTLS. The same-binary diagnostic disables TCP to measure that transport difference. Source explains the mechanisms; it does not assign CPU percentages.
croc compression is a separate variable. Both default and --no-compress are shown, including where the latter wins. Disk versus RAM also changes flush costs, so neither is silently substituted for the other.


Method and limits
The loopback matrix has 3 interleaved trials per tool and case. Each suite uses identical input bytes, warm input cache, fresh output directories and SHA-256 verification after timing. File and directory fsync are added to both tools before durable completion. Native receiver exit and sender readiness remain separate. No privileged cache dropping or host isolation.
Local CD Worker and croc relays run on the PC. Worker control storage stays in RAM for both output-storage suites. Auto allows direct discovery; the CD route evidence below each result records what actually happened. Croc's textual discovery messages do not prove its actual direct route. Forced relay disables local discovery.
The planned physical LAN suite sends 128 MiB of random bytes from this PC to Ubuntu at 192.168.1.8. Identical binaries run at both ends. CD uses a reverse SSH tunnel only for local Worker rendezvous; croc uses a private relay on the receiver machine with local discovery disabled. Bulk traffic crosses the LAN once, but rendezvous differs. LAN timing includes SSH receiver launch. RAM output is not physical persistence.
These are CLI tests. They do not measure browser, Android, public internet relay, packet-loss, directory-tree or concurrent-transfer performance. CD's numeric share code and croc's PAKE have different security properties; equal elapsed time is not evidence of equal security.
PC: 13th Gen Intel(R) Core(TM) i5-13420H, 12 logical CPUs, Linux 7.2.8-9-omarchy. CD includes preexisting uncommitted transport improvements. Browser tuning is tracked in Prof #63; each data file records its own measurement time. The binary hash identifies the tested snapshot.
