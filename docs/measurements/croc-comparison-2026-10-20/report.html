What the numbers say

croc is 2.63× faster than CD on the disk loopback test.

The 256 MiB median is 3.568 seconds for CD versus 1.358 seconds for croc. Removing croc compression reduces its median to 0.615 seconds. The payload is random, so compression adds work without shrinking it.

These numbers measure this checkout, including its uncommitted changes. They are not a claim about every CD release, internet connection, browser, or Android device.

Start by profiling the Pion direct path, comparing TCP and WebRTC on the same revision, and timing file flush separately. Keep WebRTC for browsers and NAT traversal; an authenticated TCP lane can serve reachable CLI peers.

Method and limits

LAN comparison incomplete. One CD transfer of 64 MiB completed at 5.10 MiB/s with direct transport verified. croc receive timed out after 180 seconds using default public rendezvous. No comparative LAN or internet speed claim can be made.

Identical random payload per suite, three interleaved trials per mode, and SHA-256 verification after every receive. Loopback tests use a local CD Wrangler relay and a local croc relay. croc LAN discovery is disabled for those tests so it uses the specified local relay. CD defaults may upgrade to WebRTC. Timing starts at receiver launch and ends at receiver exit; hashing the received file happens afterward. Sender readiness is recorded separately. The chart uses medians, not the fastest run.

Host: Intel i5-13420H, 12 logical CPUs, Linux 7.2.8, Node 26.10.0. Disk suite writes to the home filesystem; RAM suite uses /dev/shm. The host was not isolated from background activity. Three runs show direction, not a confidence interval. The experimental build starts from c1df17e; this checkout starts from 5723202 and is dirty. CLI defaults use numeric codes; this benchmark does not establish security equivalence with croc.
