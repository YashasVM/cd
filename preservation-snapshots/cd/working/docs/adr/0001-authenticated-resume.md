# Authenticated resume, first implementation cycle

Decision for issue #15 after coordinator and all three worker reviews; implementation begins only after Wave 3 integration.

Resume is opt-in v2. Existing v1 links, codes and clients retain their current behavior. No discovery, paired devices, compression, paid service or relay payload storage. One named byte source per handoff; bundles must regenerate identical bytes.

Root identity is a 16-byte transfer ID and 32-byte master capability. Resume uses the private capability, never an expired numeric code. CLI private capability store under CD_STATE_DIR is mode0600; exported checkpoint never contains master secret. Browser private capability and checkpoint live locally with OPFS staging. Explicit CLI commands: cdx send --resumable <paths>; cdx send --resume <rootID> <paths>; cdx receive --resume <privateLink> --out <path>. Resumable send initially produces private link (JSON may include rootID); browser sends opt-in retain progress, resumes via same private link and reselected identical source after restart. Browser without durable OPFS staging must explain restart resume unavailable.

Relay /ws/v2/<rootID> has separate root namespace, retaining sender/receiver admission hashes for24h independently of sockets. Initial sender registers hashes; reconnect proves distinct sender token. Receiver proves receiver token. Sender token is a separate random32byte secret stored only in sender private storage, preventing receiver capability holders from impersonating sender. Receiver token is HKDF-SHA256(master,salt=rootID,info='cd-transfer-v2 receiver join'). Relay stores SHA256 hashes of both. Each role contributes a fresh random32byte nonce and HMAC-SHA256(master,'cd-transfer-v2 '+role+' nonce' bytes||rootID||nonce) proof; relay forwards proofs but cannot forge them. Active sender/receiver cannot be silently replaced. Authenticated fresh session only after interruption; unauthenticated or stale-session peers rejected. Sender joins include sessionNonce and proof; receiver joins include receiverNonce and proof. Accepted/peer-joined events bind both to the current persisted session. On either socket loss, the session becomes interrupted and surviving peer is notified/closed; old-session frames/joins are rejected. A root allows at most128 sessions and retains nonce history until expiry. A paired session cannot be replaced. An authenticated final complete control marks terminal24h tombstone; terminal roots never reopen. v2 never downgrades to v1.

Sender generates cryptographic32byte sessionNonce freshly for every new session, including every restart/reconnect. Receiver also generates fresh receiverNonce on every connection attempt. Both peers verify the other's nonce proof and bind both nonces; neither can be tricked by the relay into resetting under an old key. Receiver only starts record counters for this newly authenticated session. Frame keys HKDF-SHA256(master, salt=rootID||sessionNonce||receiverNonce, info='cd-transfer-v2 sender frames' or 'cd-transfer-v2 receiver frames'). v2 record header version2; AES-GCM nonce direction prefix CDS2/CDR2 + uint64 sequence; AAD header||rootID||sessionNonce||receiverNonce. Encrypted offer and final END bind wholeSHA256 and exact size; END includes counts+wholeSHA256, not counts alone. Direct path carries identical encrypted v2 records if supported; reliable relay acceptable first v2 mode, no nonce-reset workaround.

Checkpoint metadata<=16KiB, join<=2048bytes, encrypted frames<=1MiB,256KiBchunks. File sizes must fit JS safe integer for cross-client v2; browser staging uses OPFS with quota failures actionable, never full-file RAM. Incremental SHA256 keeps digest memory bounded. Checkpoint version2 fields: role, rootID, filename, exact size, chunkSize256KiB, wholeSHA256, durable offset, prefixSHA256, staging identity, destination binding, expiresAt, priorSessionNonce, MAC. Receiver MAC key HKDF-SHA256(master,salt=rootID,info='cd-transfer-v2 receiver checkpoint'); sender MAC key derives from private sender token with info='cd-transfer-v2 sender checkpoint'. Canonical MAC input is each field in fixed order as UTF8 strings, preceded by uint32BE byte length; version and numbers decimal canonical strings. Field order: version,role,rootID,filename,size,chunkSize,wholeSHA256,offset,prefixSHA256,stagingID,destination,expiresAt,priorSessionNonce. SHA fields lowercase64hex, expiresAt unix milliseconds; both session nonces43char base64url. MAC base64url HMAC-SHA256, compared constant-time. Shared golden fixture checks exact bytes, MAC, HKDF, record ciphertext in Go and JS.

Receiver flushes/fsyncs staging before advancing checkpoint; checkpoint atomic persistence, never ACK uncommitted retained bytes. Restart authenticates checkpoint (filename exact UTF8 safe basename; stagingID opaque basename never an arbitrary path), validates expiry/file identity/chunk boundary (offset%256KiB=0 OR offset=exactsize)/offset<=size, rehashes exact durable prefix, truncates staging beyond checkpoint offset. Prefix checkpoint is MAC-protected; sender verifies offered offset/prefix against current source and full immutable digest before skipping. Only changed/tampered data rejection, no accepting a different source under same root. Completion checks whole digest across retained and newly written bytes before publication.

24h retention with expiresAt fixed at root creation; checkpoint must not extend it. CLI staging is an exclusive mode0600 adjacent file and checkpoint binds normalized final destination/staging basename, rejecting symlinks or replaced entries. Browser sender resume requires reselecting identical source; receiver resume uses same private v2 link. Expired cleanup checks a bounded batch of local records on startup (max128 perpass); browser cancellation and CLI receiver cancellation remove checkpoint/staging; interrupting a foreground CLI sender acts as a pause and retains its private resume record; network interruption keeps only committed progress, completion cleans checkpoint after destination is finalized. Resume is explicit rather than endless automatic reconnect. Shared protocol fixtures and tests prove distinct session ciphertext after sequence reset and rejection of stale session, changed source, wrong token, modified offset/digest/MAC, and corrupted/truncated staging.

Final relay completion control is a receiver-role message {type:"complete",protocol:"cd-transfer-v2",sessionNonce,receiverNonce}; it is accepted only on the authenticated current receiver socket AFTER encrypted COMPLETE was forwarded. Sender waits for authenticated encrypted COMPLETE before cleanup. Closing a socket alone marks interruption, never completion.
