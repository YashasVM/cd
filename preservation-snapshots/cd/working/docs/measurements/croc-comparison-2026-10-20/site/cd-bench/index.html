What changed

The CLI now offers an authenticated TCP lane for reachable CLI peers. AES-GCM still protects every record. New CLIs negotiate larger encrypted chunks while older receivers retain their original limits. Receiver decryption consumes owned records in place, removing a full plaintext allocation per chunk. Folder sizing now counts ZIP metadata instead of checksumming synthetic payload bytes.

Reverse TCP is tried first on a shared subnet, then a serialized forward attempt and WebRTC fallback. A bounded 50 ms setup grace avoids sending large payloads twice while the direct path opens. Reverse failure can still add up to three seconds before forward fallback.

Authentication, byte counts, sequence checks, final file fsync, and fallback remain. The resumable v2 protocol and Android receiver do not inherit these v1 transport gains.

Physical LAN result

The Ubuntu Ethernet adapter is negotiated at 100 Mbps. Beating croc's current measured 64 MiB median by 1.5× would require more than 116 Mbps before protocol overhead. This hardware cannot support that multiplier on incompressible data.

How to read the evidence

Each workload uses identical bytes across tools. Random and compressible payloads are separate. Tool order rotates between trials. SHA-256 verification happens after transfer timing. Local relay state stays in RAM for both disk and RAM output suites, so local SQLite disk writes do not masquerade as protocol overhead. Input cache is warm; the benchmark does not claim cold-cache performance.
